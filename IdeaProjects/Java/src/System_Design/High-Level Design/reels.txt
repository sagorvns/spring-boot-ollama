## ✅ 1. Problem Statement

Design a platform that allows users to:

* Upload short videos (15s–60s)
* View, like, comment, and share videos
* Infinite scroll feed (recommendation-based)
* Follow/unfollow users

---

## 🎯 2. Requirements

### ✅ Functional

* Upload videos (with music)
* Auto-play scrollable video feed
* Like, comment, share, follow
* Recommendation engine
* User profile page

### ✅ Non-Functional

* Low latency playback
* Scalable for millions of users
* High availability
* Video processing pipeline
* CDN-based delivery

## ⚙️ 4. Component Breakdown

### 🎬 **Video Upload + Processing**

* User uploads video → Kafka → Encoder service (FFMPEG)
* Create multiple quality variants (240p, 480p, 720p)
* Generate thumbnails, watermark, duration check

### 🌐 **CDN Delivery**

* Processed videos + thumbnails uploaded to S3
* Delivered via **CDN** to reduce latency globally

### 🤖 **Recommendation System**

* Feed is not just chronological — based on:

  * Engagement: likes, shares, replays
  * User interaction
  * Follower graph
* Can be batch-based (Spark) or real-time (Redis, Flink)

### 💬 **Likes, Comments**

* Likes, shares in **Redis + Cassandra** (or DynamoDB)
* Comments: persisted in MongoDB with pagination

### 👥 **Follow System**

* Stored in graph DB (Neo4j) or PostgreSQL with adjacency list

* `video_id`, `user_id`, `upload_time`, `duration`, `cdn_url`, `thumbnail_url`

### Like Table (NoSQL)

* `video_id`, `user_id`, `timestamp`

### Comment Table (MongoDB)

* `comment_id`, `video_id`, `user_id`, `text`, `created_at`

## 🧠 7. Interview Cross Questions + Answers

| ❓ Question                                       | ✅ Answer                                                                                   |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| **Why Kafka in video upload pipeline?**          | Decouples upload from processing. Supports retries, scale, buffering during spike uploads. |
| **How to avoid duplicate videos?**               | Use hash-based deduplication before storage                                                |
| **How to handle abuse or NSFW uploads?**         | Content moderation via ML models + human review + flag/report APIs                         |
| **Why CDN?**                                     | Faster global delivery of static video content; reduces origin load                        |
| **How is the feed ranked?**                      | Based on watch time, replay rate, likes, past behavior (collaborative filtering)           |
| **How do you ensure consistency in likes?**      | Store in Redis + asynchronously persist to NoSQL DB for reliability                        |
| **How to avoid hot videos breaking the system?** | Cache metadata + video URLs in Redis; offload to CDN                                       |
| **How to support infinite scrolling?**           | Cursor-based pagination and lazy loading with pre-fetching                                 |

## 📈 8. Non-Functional Design Notes

| Concern       | Solution                                 |
| ------------- | ---------------------------------------- |
| Latency       | CDN + client buffering                   |
| Availability  | Replicated DBs, stateless microservices  |
| Scalability   | Kafka, NoSQL, sharded DBs                |
| Security      | JWT Auth, signed CDN URLs, rate limiting |
| Observability | Prometheus + Grafana + ELK               |
| Video Abuse   | AI + moderation dashboard                |
