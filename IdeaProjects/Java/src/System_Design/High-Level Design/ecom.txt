## ✅ 1. Problem Statement

Design a scalable **E-commerce Platform** that enables:

* Product catalog browsing
* Search/filter products
* Shopping cart and checkout
* Online payments
* Order management
* Reviews and ratings
* Scalability and fault tolerance

---

## 🎯 2. Requirements

### ✅ Functional Requirements

* User registration, login
* View/search/filter products
* Add to cart, place order, payment
* Track orders
* Product reviews and ratings
* Seller onboarding (multi-vendor)

### ✅ Non-Functional Requirements

* High availability and scalability
* Low latency for catalog search
* Secure payment processing
* Strong consistency for inventory and orders
* Fault tolerance
* Eventual consistency for product info sync

## 🔍 4. Key Microservices & Responsibilities

| Service                  | Description                                                           |
| ------------------------ | --------------------------------------------------------------------- |
| **Product Catalog**      | Stores item details, images, category, price                          |
| **Search Service**       | Uses Elasticsearch for fast product search                            |
| **Cart Service**         | Handles shopping cart in Redis (fast, session-based)                  |
| **Order Service**        | Manages placing orders and transitions (Placed → Shipped → Delivered) |
| **Inventory Service**    | Updates stock and locks items during order placement                  |
| **Payment Service**      | Integrates with payment gateways (Stripe/Razorpay)                    |
| **Review Service**       | Product ratings + reviews, stored separately                          |
| **Notification Service** | Email/SMS updates via queues                                          |
| **Analytics Service**    | Clickstream tracking, product impressions                             |

---

## 🔁 5. Flow: Place Order

1. User logs in and browses catalog
2. Adds items to **Cart Service** (stored in Redis)
3. Clicks “Checkout” → request goes to **Order Service**
4. **Inventory Service** locks item (optimistic locking or versioning)
5. **Payment Service** processes transaction
6. If success → status: `PAID`, else rollback
7. **Order** and **Inventory** updated atomically
8. Triggers **Kafka Event** → `order.placed`
9. Async notification sent to **User**
10. Scheduled job handles delivery flow

### 🗃️ Product Table

* `product_id`, `title`, `desc`, `price`, `stock`, `seller_id`

### 🛒 Cart Table

* `cart_id`, `user_id`, `product_id`, `qty`, `added_at`

### 📦 Order Table

* `order_id`, `user_id`, `status`, `payment_status`, `shipping_address`, `created_at`

* `order_id`, `product_id`, `qty`, `price_at_time`

### 📉 Inventory Table

* `product_id`, `stock`, `reserved`, `last_updated`

### 🌟 Review Table

* `user_id`, `product_id`, `rating`, `comment`, `timestamp`

## 🧠 8. Common Interview Cross-Questions

| Question                                            | Answer                                                    |
| --------------------------------------------------- | --------------------------------------------------------- |
| **How do you scale product search?**                | Use Elasticsearch with autocomplete, filters, sharding    |
| **What happens if payment fails?**                  | Order is marked as `FAILED`, inventory is released        |
| **How do you handle high traffic during sales?**    | Use CDN, Redis for cart, rate limiting at gateway         |
| **How do you prevent race condition in inventory?** | Optimistic locking or DB row versioning                   |
| **How do you ensure idempotency?**                  | Use idempotency keys for critical APIs (orders, payments) |
| **How are order updates sent to users?**            | Kafka → Notification Service (SMS/Email)                  |
| **Can sellers update product info?**                | Yes, via Admin Portal (secured APIs)                      |

## ⚙️ 9. Scalability & Optimization Techniques

| Layer            | Strategy                                        |
| ---------------- | ----------------------------------------------- |
| **Catalog**      | Cache frequently viewed products using Redis    |
| **Search**       | Use Elasticsearch clusters with index tuning    |
| **Cart**         | Stateless cart stored in Redis per user session |
| **Orders**       | Write-heavy DB partitioned by user/region       |
| **Payment**      | Retry-safe using queues + idempotency key       |
| **Notification** | Use Kafka or RabbitMQ for async delivery        |
| **CDN**          | Host images, thumbnails close to user location  |

## 🔐 10. Security & Compliance

* HTTPS everywhere
* Role-based access for sellers vs users
* Rate limiting (via API Gateway)
* CSRF + JWT token for session security
* PCI compliance for payments
* XSS & SQL injection prevention via validation libraries
