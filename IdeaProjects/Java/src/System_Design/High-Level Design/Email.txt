## 🧠 1. Problem Statement

Design an email system that enables users to:

* Send and receive emails
* Organize emails (folders, labels)
* Search emails by keywords
* Support attachments
* Access via web/mobile
* Handle spam filtering
* Sync in real-time across devices

---

## ✅ 2. Requirements

### 🔹 Functional Requirements:

* User registration, login (auth)
* Compose and send email (To, CC, BCC)
* Receive and read email
* Search by subject, body, sender
* Organize (delete, archive, labels, folders)
* Spam detection
* Attachment support

### 🔹 Non-Functional Requirements:

* High availability & reliability
* Message delivery guarantees (at-least-once)
* Fast search indexing
* Low latency (under 200ms UI response)
* Secure data storage & transmission (encryption)
* Scalability (millions of users)

## 🧩 4. Components Explained

| Component                | Description                                                  |
| ------------------------ | ------------------------------------------------------------ |
| **API Gateway**          | Handles REST/WebSocket requests                              |
| **Auth Service**         | Manages user login, sessions (OAuth2/JWT)                    |
| **Compose/Send Service** | Parses email headers, body, validates users                  |
| **Kafka Queue**          | Buffers email send requests for delivery                     |
| **Delivery Service**     | Sends via SMTP or stores internally (for same domain)        |
| **Storage**              | Stores email metadata (PostgreSQL), content (S3), index (ES) |
| **Search Indexer**       | Tokenizes and indexes subject/body for fast search           |
| **Spam Filter**          | ML-based engine to flag spam (Bayesian, Naive Bayes, etc.)   |

## 🔁 6. Flow Diagram: Sending Email

```
1. User clicks Send
2. API Gateway → Compose Service
3. Compose validates → Pushes to Kafka queue
4. Email Delivery Service reads from Kafka
5. SMTP server sends email → response stored
6. Save email in sender’s “Sent” folder
7. If recipient is internal → directly store in their inbox
```

---

## 🔁 7. Flow Diagram: Receiving Email

```
1. SMTP Server receives incoming email
2. Spam filter service scores it
3. If spam → label & send to spam folder
4. If valid → store in receiver’s inbox
5. Index email content in Elasticsearch
6. Push notification via WebSocket
```

---

## 🔒 8. Security & Spam Protection

* TLS for data-in-transit (SMTP+STARTTLS)
* Hash passwords using bcrypt
* Use SPF, DKIM, and DMARC to validate senders
* ML models or rule-based scoring for spam
* Quarantine or auto-delete known malicious content

## ⚡ 9. Scaling Strategies

| Component      | Scaling Strategy                            |
| -------------- | ------------------------------------------- |
| API Layer      | Stateless microservices, scale horizontally |
| Email Delivery | Kafka + parallel SMTP workers               |
| Search         | Partition ElasticSearch by userId or domain |
| Storage        | Use S3 for bodies, DB for metadata          |
| Spam Filter    | ML inference service behind queue           |
| WebSocket      | Sticky sessions, scale horizontally         |

## 📚 10. Interview Cross-Questions (With Answers)

---

### ❓ How do you ensure message delivery?

✅ Use Kafka for durability → retry on failure. Mark status as SENT only after successful SMTP acknowledgment.

---

### ❓ How do you handle search?

✅ Use ElasticSearch to index subject, body, sender fields with inverted indexes and text analyzers.

---

### ❓ How is spam detected?

✅ ML-based scoring engine (e.g., Logistic Regression) or rule engine → spam score threshold → move to spam folder.

---

### ❓ How do you support attachments?

✅ Upload to blob store (S3) → store link in metadata → secured via signed URLs.

---

### ❓ How is email synced across devices?

✅ Store status centrally → all devices subscribe via WebSocket for inbox update events.

---

### ❓ How are folders/labels handled?

✅ Folder is a tag in DB. One email can have multiple labels. UI renders accordingly.

---

### ❓ What happens when SMTP fails?

✅ Retry `n` times. If persistent failure, notify sender and store in "Failed to Send".
